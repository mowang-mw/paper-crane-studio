# 已知限制与范围边界

## 定位

当前成果是一个可运行、可演示、可追溯的本地多模型动漫制作平台原型。它证明了 Qwen3-4B、Animagine XL 4.0、Qwen3-TTS 与 FFmpeg 的真实集成，不宣称达到商业动画制作系统或生产级多用户服务的完整能力。

## 当前模型质量限制

### 剧本

本机采用量化 Qwen3-4B，适合短故事和 3-5 个镜头的结构化生成。复杂长篇叙事、深层人物弧线和高一致性世界观受模型规模、上下文和提示约束限制。

### 图片

Animagine XL 4.0 能生成具有动漫风格的真实关键帧，但单帧细节、文字、手部、复杂构图，以及跨镜头角色服装和身份一致性仍可能波动。现有角色描述提供基础约束，不等同于角色一致性系统。

### 语音

Qwen3-TTS 0.6B CustomVoice 能输出真实中文旁白，Serena 为默认音色、Vivian 可选。自然度、情绪控制、特殊读音和长文本韵律仍受轻量模型限制；当前没有专业配音编辑和音素级校正。

## 当前平台能力限制

- 画面由静态动漫关键帧构成；FFmpeg 提供 `static`、中心缩放和克制平移等镜头运动。
- 没有角色级连续动作、口型同步或真实连续视频生成。
- 没有专业非线性时间线、逐帧剪辑、关键帧曲线编辑和复杂音频工程界面。
- 当前为单机、单用户、单 Worker；不面向高并发、多租户或分布式 GPU。
- SQLite 与本地文件系统适合本地演示，不是云端对象存储和跨节点任务方案。
- 背景音由用户上传；平台验证格式和解码，但不判断或授予版权。
- ducking 基于旁白音轨电平，不是语义级语音活动编辑器。
- Poster 是从成片抽帧生成，不是独立封面生成模型。
- `MEDIA_RERENDER` 只能复用同一项目内完整、成功、可解码的真实来源素材；不会补生成缺失资产。

## 有意不做的能力

以下内容是当前范围内主动控制复杂度的结果，而不是被遗漏的既定需求：

- 微服务拆分、Redis、Celery、Kubernetes 和分布式调度。
- 登录、权限、多用户协作、团队审阅和云端共享。
- 专业 NLE 时间线、拖拽剪辑器和完整资产管理系统。
- ControlNet、角色一致性专用模型和训练流程。
- 音乐生成模型、内置来源不明的背景音乐和版权声明。
- 真正的视频生成模型或已实现的 VideoProvider。

这些能力会显著改变数据契约、资源调度和验收范围。当前架构优先保证真实多模型链路在指定硬件上稳定演示。

## 硬件与部署边界

已验证硬件是 RTX 4060 8GB。三个模型按阶段加载并释放，不能假设同时驻留。工作站 24GB+、48GB、云 GPU 和闭源 API 只在 [模型升级指南](model-upgrade-guide.md) 中作为架构扩展建议，本项目没有实测这些环境。

## 如何正确描述成果

推荐描述：

> 一个在 8GB 显存本机上跑通真实文本、图像、语音和 FFmpeg 成片链路的多模型动漫制作平台原型，具备任务快照、失败边界、媒体复用和 Manifest 追溯。

不应描述为：

- 商业级或专业动画生产系统。
- 已解决角色一致性或连续动作生成。
- 已集成视频生成模型。
- 可零代码无缝替换任意模型。
- 已验证云端、工作站或大规模生产部署。
- 全自动、无需人工检查或 production-ready。

## 下一阶段判断

更大同类模型主要提升生成质量上限；角色一致性、连续视频、专业编辑和多用户运行则需要平台能力扩展。两者应分别设计和验收，避免把模型升级误写成系统能力已经完成。
