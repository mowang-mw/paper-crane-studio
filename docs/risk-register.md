# 风险登记册

## 1. 评级方法

- 概率：高（很可能发生或当前条件已经存在）、中（有现实触发路径）、低（不常见但需防护）。
- 影响：高（阻断成片、数据/密钥安全或演示）、中（影响质量或消耗半天以上）、低（局部体验问题）。
- 处置优先级：高概率×高影响首先消除关键路径依赖，而不是只写监控。

风险在 M0、M1、M3、M5 和演示冻结里程碑复核。资源和模型相关结论必须用目标机数据更新，不能长期保留为主观判断。

## 3. 最高优先级风险的决策

### 3.1 无 API 与模型故障

这是已知约束，不等待其“可能发生”。工程保底的最小页面、Job、素材和导出必须在 Mock 下可用；但真实文本和真实图像仍是真实 Provider 目标，需要在保底完成后按许可实测，不得因无远程 API 而直接跳过本地候选。

### 3.2 8GB 显存

不要用“模型文件小于 8GB”证明可以运行。峰值还包含激活、文本编码器、VAE、KV cache、CUDA 工作区和框架开销。每个真实模型单独记录：磁盘、空闲显存、峰值显存、系统 RAM、启动时间、生成时间、连续运行和释放资源结果。未记录前状态是 `UNVERIFIED`。

### 3.3 视频质量与速度

不通过优化视频模型来消除此风险，而是移除其关键路径依赖。真实视频只是可替换单镜头实验；FFmpeg 运镜是正式产品能力，UI 和 manifest 如实标记。

### 3.4 进度

范围降级顺序固定为：SSE/美化 → 真实 TTS → 自动重试/取消 → 租约/心跳/复杂幂等与两阶段恢复 → 更多候选。全 Mock、四态 Job、持久化、FFmpeg、必要追溯、真实文本接入目标、真实图像实测与证据责任以及最终缓冲不可删除。图像实测失败后停止更换候选，转为证据包和替代演示。

## 4. 风险复核记录模板

每次里程碑记录：

```text
日期：
风险 ID：
状态：OPEN / MITIGATED / OCCURRED / ACCEPTED / CLOSED
新证据：官方链接或本机测试记录
概率/影响变化：
已执行缓解：
是否触发兜底：
负责人及下次复核日：
```

“关闭”必须有证据；仅因为进入演示日而停止处理，不等于风险消失。
