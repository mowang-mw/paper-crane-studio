# M6-1 界面打磨

## 设计目标

M6-1 将功能型长页面整理为适合课堂演示的动漫制作工作台。界面以内容和任务状态为中心，使用深色工作台头部、浅色制作区域和深色成片区域建立层级；暖橙、青绿只承担主操作、完成状态和 GPU 提示等有限强调。

本轮仅调整前端展示与交互，不修改后端 API、数据库、Worker、Provider、FFmpeg 或模型参数。

## 信息架构

界面固定表达四个阶段：

1. 项目与故事：创建、选择项目，填写故事并载入演示样例。
2. AI 剧本：选择 Script Provider、镜头数量，提交和观察 Job。
3. 动漫画面：审阅 ScriptV1、角色与场景，生成并查看关键帧。
4. 配音与成片：选择 Serena / Vivian，查看逐镜头音频状态，播放和下载最终成片。

顶部同时显示产品名、当前项目、系统状态和模型状态入口。工作流导航显示当前、已完成、可以开始和未开始状态，并允许跳转到已经可用的阶段。

## 主要组件

- `StageNavigation`：四阶段工作流和阶段状态。
- `ProviderSelector`：Script Provider、真实 / Mock 来源、模型和在线状态。
- `JobPanel`：总体进度、当前阶段、镜头进度、Provider、耗时和失败重试。
- `FailureCard`：面向用户的摘要、推荐动作和可折叠技术详情。
- `ShotImage`：真实关键帧、大图入口和媒体加载失败占位。
- 镜头卡片：画面、镜头说明、旁白、时序延长和 seed / RTF 追溯。
- 成片区域：大尺寸播放器、真实链路摘要、MP4 与 Manifest 下载。

## Provider 与 GPU 状态

Provider 徽标统一区分真实模型、Mock 保底、可用、离线和配置不完整。模型链路在首屏明确显示为 `Qwen -> Animagine -> Qwen3-TTS -> FFmpeg`。

8GB 显存交接提示保留后端真实状态：平台不会自行结束外部模型进程。界面会说明当前冲突、为何需要分阶段运行，以及用户应停止文本模型、ComfyUI 或释放 GPU 后重新检查 Provider。

## 响应式策略

- 桌面端以 1240px 工作区为主，项目列表与编辑区、视频与导出信息采用双栏布局。
- 中等屏幕将镜头卡片和结果区转为单栏。
- 小屏幕将流程导航改为 2x2，项目列表限制高度，主操作与表单保持可触达。
- 固定比例视频和稳定的镜头媒体区域避免加载状态造成明显布局跳动。

## 可访问性处理

- 保留键盘可见焦点和阶段跳转后的焦点定位。
- 主表单具备字符计数、`aria-invalid` 和关联提示。
- Job 使用原生 `progressbar` 语义，通知、错误和 GPU 状态使用 live region。
- 图片提供描述性替代文本、明确的大图链接和加载失败提示。
- 音频 URL 可用时提供原生播放控件；不把后端文件系统路径伪装成浏览器 URL。
- 禁用按钮保留明确原因，长 ID、模型名和路径允许换行或省略。
- 遵循 `prefers-reduced-motion`。

## 保留的技术限制

- 真实模型必须在 RTX 4060 8GB 上分阶段运行，界面不能代替用户关闭外部进程。
- 逐镜头音频只有在后端返回公开媒体 URL 时才可单独试听；当前仅返回本地 WAV 路径时，音频仍通过最终 MP4 播放。
- Mock 与真实产物不会混淆；真实 Job 失败不会在界面中伪装成 Mock 成功。
- 当前仍是单机本地工作流，不包含多用户协作、在线存储或远程模型管理。

## 人工验收清单

- [ ] 后端离线时首屏和错误提示可理解，页面不崩溃。
- [ ] 无项目时空状态、Demo 填充、字符限制和创建项目正常。
- [ ] 项目切换、删除确认和正在运行时的禁用状态正常。
- [ ] Mock 与 llamacpp Provider 状态、镜头数选择和主操作层级清楚。
- [ ] Job 的排队、运行、成功、失败、GPU 交接和手动重试状态正确。
- [ ] ScriptV1、角色、场景和镜头信息没有丢失。
- [ ] 真实图片可加载、可点击查看大图；失败时显示占位。
- [ ] Serena / Vivian 切换、旁白进度、时长、RTF 和镜头延长提示正确。
- [ ] 最终视频可播放，MP4 与 Manifest 下载链接保持不变。
- [ ] 在约 1440px、900px 和 390px 宽度下无明显重叠或横向溢出。
- [ ] 仅用键盘可到达主要操作，焦点清晰。
